## Real vs mocked

| Thing | Real or mocked |
|---|---|
| Transcript format + parser | **Real.** Written against an actual `~/.claude/projects` transcript found in this sandbox, not from the brief. |
| `MEASURED USAGE` numbers | **Real.** Straight out of the `usage` blocks Claude Code writes. |
| `CONTEXT COST` split | **Estimated**, anchored to measured totals (see *Token estimation*). |
| Tool-schema token figures | **Estimated from a hand-written table** (`tokens.TOOL_SCHEMA_TOKENS`). The softest number in the app. |
| Live session streaming | **Real.** Spawns `claude -p --output-format stream-json` and parses its actual output. |
| Permission handling | **Real.** Observed `system/permission_denied` in a live run and rendered it. |
| Terminal | **Real** `node-pty` shell. |
| `fixtures/projects/` | **Synthetic**, generated by `fixtures/generate.py` in the exact real format. |
| `sandbox-repo/` | Real files, deliberately trivial — a safe target for live runs. |

Nothing in the UI is a hardcoded mock. Every number on screen is computed from a
transcript or a live process.

## Decisions, and why

### Trusted the disk over the brief

The sandbox turned out to have a real `~/.claude/projects` (this session's own
transcript) and a working, authenticated `claude` CLI. So both the parser and
the runner were written against observed behaviour. **Where the brief and
reality differed, reality won.** The differences that mattered:

**Transcript format.** Line types are much broader than `user`/`assistant`:
also `attachment`, `last-prompt`, `atis-latch`, `queue-operation`, `summary`.
Unknown types are skipped as inert metadata rather than raising, so a format
change degrades to missing detail instead of a crash.

**One API request emits several assistant lines that all repeat the same
`usage` block.** Summing per line triple-counts your token usage. Deduped on
`requestId`. This is the single easiest thing to get wrong here.

**`attachment` lines are injected context** — skill listings, system reminders,
tool listings — that cost real tokens and that no UI I know of shows you. On the
real transcript they were **22% of the whole conversation**. Surfacing that is
now a headline row in the report.

**Live stream vocabulary.** The brief described a simple message stream. The CLI
actually emits `system/init`, `system/permission_denied`,
`system/post_turn_summary` (with `status_category` and `needs_action`),
`system/task_summary`, `rate_limit_event`, and a terminal `result` carrying
`permission_denials` and real cost. `post_turn_summary.needs_action` turned out
to be the perfect signal for the amber "waiting on you" dot — better than
anything I would have invented.

**The child inherits `CLAUDE_SESSION_ID` from the environment.** A run spawned
without an explicit `--session-id` wrote into *another session's* transcript.
`runner.py` now always pins a fresh session id and strips that variable from the
child env. This would have been a nasty, silent data-corruption bug.

### Repo path comes from `cwd`, not the directory name

The directory encoding (`-Users-ayan-code-harbor`) replaces `/` with `-` and is
lossy — a repo with a dash in its name is indistinguishable from a path
separator. Every conversation line carries an exact `cwd`, so that wins;
`decode_project_dir()` is only a fallback.

### Token estimation is a heuristic, deliberately

`tiktoken` installs but cannot fetch its BPE files through the sandbox proxy,
and it would be the wrong vocabulary for Claude anyway. So: chars-per-token
ratios (3.8 prose / 3.1 JSON-and-code, both in `config.py`), calibrated against
the measured `usage` deltas in the real transcript.

**The report never leans on the heuristic where a real number exists.** It
anchors on measured totals and uses the heuristic only to *apportion* them.
Observed drift against the measured window on the real transcript: **~11%**,
which the report states in its own NOTES rather than hiding.

### The preamble is measured by difference, not guessed

At a session's first request the context holds system prompt + tool schemas +
exactly one user turn. The total is measured and the user turn is estimable, so
`preamble = first_request_tokens − estimate(first turn)` is a real number.

Only the *split* of that preamble into system-prompt vs tool-schemas uses the
soft table, and only tools the session actually called can be counted — schemas
loaded but never used fold into the system-prompt line. The UI labels the
preamble `measured` or `estimated` accordingly. If you want the honest unsplit
number, that's what the preamble row is.

### One event shape for live and historical

`events.py` normalises both a parsed `.jsonl` line and a live `stream-json` line
into the same wire format, so the agent panel has exactly one renderer.
`WS /ws/replay/{id}` plays a historical transcript through the live path, which
is a cheap way to demo streaming without burning tokens.

### No database, no frontend framework

Transcripts are parsed on demand as instructed. The server has an mtime+size
parse cache (`server._Cache`) so a large real history stays responsive. The
frontend is vanilla JS in five files; I never hit a wall that justified more.

## Pointing at your real `~/.claude/projects`

Zero code changes. It's read in exactly one place (`config.projects_dir()`) and
already defaults to `~/.claude/projects`; the Electron app just overrides that
default to the fixtures so a fresh clone shows something. To use real data:

```bash
cd app && DESCANT_PROJECTS_DIR=~/.claude/projects npm start
```

**Two caveats before you do:**

1. **Scale.** Fixtures are 6 small sessions. A year of real history is thousands
   of transcripts, some tens of MB. The mtime cache means you pay the parse cost
   once per file per change, but the *first* load still walks everything —
   expect a slow first paint on a big history. If it's bad, the next move is to
   read only the head and tail of each file for the list view and parse fully
   on click. Not done tonight.
2. **Sidechains.** Subagent (`isSidechain: true`) events are parsed and counted
   but not visually separated from the main thread. On a transcript with heavy
   subagent use the agent panel will interleave them confusingly. The data to
   fix this is already on every event (`meta.sidechain`).

Neither is a blocker; both are noted so they aren't a surprise.

## Restyling — where the theme lives

**`app/renderer/theme.css`.** Every colour, spacing step, font stack, radius and
layout metric is a CSS custom property in that one file. `app.css` references
those variables exclusively — if you find a literal hex code or pixel value
anywhere else in the CSS, that's a bug, tell me.

Two non-obvious wins:

- **The xterm terminal theme is read out of those same variables at runtime**
  (`term.js` → `themeFromCss()`), so the terminal restyles with the app instead
  of carrying its own hardcoded palette.
- **The Monaco theme too** (`editor.js` → `defineTheme()`).

So the restyle really is a one-file edit. Current pass is deliberately plain:
VS Code Dark Modern lineage, greys carrying the UI, one blue (`--accent:
#3B82F6`) used only for selection, focus and the active-tab underline.

Status dots are `--status-running` / `--status-idle` / `--status-needs-input` /
`--status-failed`, all in the same file. The only animation in the app is the
running spinner (`--spinner-duration`).

## Known gaps and rough edges

- **Diff view (item 6) is written but not reachable.** `Editor.openDiff()`
  works and is themed, but nothing in the UI calls it yet — wiring it needs
  before/after content for an agent edit, which means either shelling out to
  `git diff` or reconstructing from `Edit` tool inputs in the transcript. Marked
  `TODO(descant)` in `app/renderer/app.js`. The editor itself opens files fine.
- **Live runs are one-shot.** Each Run spawns `claude -p`, which answers once
  and exits. There's no follow-up turn into a running process — the resume path
  (`--resume`) is implemented in `runner.start()` but no UI calls it. This is the
  biggest functional gap versus a real chat loop.
- **No file watching.** The sidebar polls `/api/runs` every 2.5s for live status
  and only re-reads transcripts on **Reload**. A live session's own transcript
  won't appear in the sidebar until you hit that button.
- **Center panel doesn't follow live runs.** Selecting a live run updates the
  agent panel but leaves whatever tab was open in the center.
- **CSP warning on boot** is expected — Monaco needs `unsafe-eval`.
- Electron `console-message` deprecation warning on newer Electron; harmless.

## Verifying without a screen

The app was developed headless. `DESCANT_SCREENSHOT=<path>` grabs the window and
exits; `DESCANT_DRIVE=<file.js>` runs an expression in the renderer first, so a
whole flow can be photographed:

```bash
cd app && DESCANT_SCREENSHOT=/tmp/shot.png DESCANT_SCREENSHOT_DELAY=8000 \
  xvfb-run -a ./node_modules/.bin/electron . --no-sandbox
```

That's how the live-run and permission-block paths were confirmed working.
