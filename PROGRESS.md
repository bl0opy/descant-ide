## What works

### Item 1 — context-cost inspector (`backend/descant/`)

```bash
cd backend
DESCANT_PROJECTS_DIR=../fixtures/projects python3 -m descant.cli list
DESCANT_PROJECTS_DIR=../fixtures/projects python3 -m descant.cli show 93c9da93
```

Reports per session: repo, last activity, message count, and the context split
by system prompt / tool schemas / conversation — plus a conversation
sub-breakdown, cost by tool, and cost of *injected* context (attachments the
user never typed: skill listings, system reminders, tool listings). `--json` on
either subcommand for machine output; that same dict is what the HTTP API
serves.

## Real vs mocked

| Thing | Real or mocked |
|---|---|
| Transcript format + parser | **Real.** Validated against an actual `~/.claude/projects` transcript found in this sandbox — not written from the spec. |
| Token counts in `MEASURED USAGE` | **Real.** Lifted from the `usage` blocks Claude Code writes on every assistant turn. |
| Token counts in `CONTEXT COST` | **Estimated**, but anchored to measured totals (see *Token estimation*). |
| Tool-schema token figures | **Estimated from a hand-written table** (`tokens.TOOL_SCHEMA_TOKENS`). The softest number in the report. |
| Session transcripts in `fixtures/` | **Synthetic**, generated by `fixtures/generate.py` in the exact real format. |

## Decisions and why

**Trusted the disk over the brief.** The sandbox turned out to have a real
`~/.claude/projects` (this session's own transcript), so the parser was written
against observed data. Differences from the brief's description, all handled in
`transcript.py`:

- Line types are broader than `user`/`assistant`: also `attachment`,
  `last-prompt`, `atis-latch`, `queue-operation`, `summary`. Unknown types are
  skipped as inert metadata rather than raising.
- **One API request emits several assistant lines that all repeat the same
  `usage` block.** Summing usage per line triple-counts. Deduped on `requestId`.
- `message.content` is a bare string for simple user turns and a block list
  otherwise.
- `attachment` lines are injected context that costs real tokens and is invisible
  in every UI I know of. Surfacing that is now a headline feature of the report.

**Repo path comes from `cwd`, not the directory name.** The directory encoding
(`-Users-ayan-code-harbor`) replaces `/` with `-` and is lossy — a repo with a
dash in its name is indistinguishable from a path separator. Every conversation
line carries an exact `cwd`, so that wins; `decode_project_dir()` is only a
fallback for a transcript with no usable line.

**Token estimation is a heuristic, deliberately.** `tiktoken` installs but
cannot fetch its BPE files through the sandbox proxy, and it would be the wrong
vocabulary for Claude anyway. So: chars-per-token ratios (3.8 prose / 3.1
JSON-and-code, in `config.py`), calibrated against the measured `usage` deltas in
the real transcript. The report never leans on the heuristic where a real number
exists — it anchors on measured totals and uses the heuristic only to *apportion*
them. Observed drift vs the measured window: **~11% on the real transcript**,
which is stated in the report's own NOTES rather than hidden.

**The preamble is measured by difference, not guessed.** At the first request of
a session the context holds system prompt + tool schemas + exactly one user turn.
The total is measured and the user turn is estimable, so
`preamble = first_request_tokens − estimate(first turn)` is a real number. Only
the *split* of that preamble into system-prompt vs tool-schemas uses the soft
table, and only tools the session actually called can be counted — schemas
loaded but never used fold into the system-prompt line. The report says so.

**No database.** Transcripts are parsed on demand, as instructed. If this gets
slow on a large history the fix is a parse cache keyed on `(path, mtime, size)`,
not a parallel store.

## The `DESCANT_PROJECTS_DIR` swap

Pointing this at a real `~/.claude/projects` needs **zero code changes** — it is
read in exactly one place (`config.projects_dir()`) and defaults to
`~/.claude/projects` already, so with the env var unset it Just Works.

Two honest caveats for when it meets a real history:

1. **Scale.** Fixtures are 6 small sessions. A year of real usage is thousands
   of transcripts, some tens of MB. `load_all()` parses every file on every
   request. Expect the session list to get slow; the fix is the mtime cache
   noted above, ~20 lines.
2. **Format drift.** The parser was validated against Claude Code `2.1.14`
   transcripts. Unknown line types and unknown content-block types are skipped
   rather than fatal, so an older or newer format degrades to missing detail
   instead of a crash.

## Restyling — where the theme lives

**All design tokens will live in `app/renderer/theme.css`** as CSS custom
properties: colors, spacing scale, font stacks, radii, the one accent blue.
Nothing else in the app should contain a literal color or pixel value. Swapping
the visual pass = editing that one file.
